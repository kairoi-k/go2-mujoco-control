# Phase 2 B1-B3 Acceptance Contract v2 修订案

状态：PROPOSED-AND-ADOPTED-BY-DELEGATED-AUTHORITY，2026-08-30。
基线：`phase2-b123-v1`（FROZEN）。本修订案不放宽穿越完成性的任何
物理要求；它只松开被证据判定为与穿越物理冲突的两个包络条款。
证据包：`example/cpp/experiments/_runs/ESCALATION_LOG.md`
Order-008~016 节（30 集基线 commit 23d5ced，Order-012 方差归因，
Order-014 FK 可达性，oracle 裁决 2026-08-29）。

## 修订动机（证据摘要）

1. 结构缺陷全部修复后（support gate 意图分类、事务诚实化、执行窗口、
   支撑保持与释放、前移相），30 次独立 episode 全门通过率 0/30，
   穿越条款（机身+全足越过终面）0/30，见 Order-013 统计节。
2. Order-012 的 20 运行聚合证明：无早期可控预测量分离成败——结果对
   初始接触时序混沌敏感，running-trot 动态穿越是概率事件而非可验收的
   确定性行为。
3. Order-014 的 FK 证据：后足平台目标在机身 base_x≈0.50 时径向
   0.53m，超出 Go2 后腿最大可达 0.426m——动态包络下机身不停下前移，
   后足物理上永远上不了 5cm 台。
4. v1 的全程固定 0.30m/s 速度 profile + 禁止刹车 + 冻结步态拓扑，
   与"机身必须先前移后足才可达"的物理链直接冲突。

## 修订条款（仅这两条，其余全部继承 v1 冻结）

V2-A【地形转移窗口的速度剖面】：当 planner 宣布 terrain transfer
active 起，到穿越完成（机身与全足越过终面）或 transfer abort 止，
速度脚本允许切换为地形自适应剖面：接近段仍 0.30m/s；转移窗口内允许
受控减速至爬行速度（不低于 0.05m/s，不允许完全刹停超过 1.0s）；
穿越完成后 1.0s 内恢复脚本速度。窗口外 v1 条款原样适用（首末
v_cmd 容差 ±0.020m/s、禁刹车、单速度权威全部保留）。

V2-B【转移窗口的步态】：转移窗口内允许从 running-trot 切换为
准静态 crawl（任意时刻 ≥3 接触），窗口外恢复冻结的 Phase1 步态
profile。窗口内的 contact 一致性、planned/measured 转移一致、零碰撞、
每腿实测力支撑触地等全部 v1 条款不变。

## 不变的底线

lidar-only 输入、禁读真值/XML/坐标/阶次、零碰撞、穿越完成性、
0.45s 稳定过场证据、证据 manifest 要求、B2/B3 场景定义——全部
继承 v1，一字未动。本修订案的通过标准与 v1 同为定量 PASS，只是
包络从"匀速动态穿越"改为"允许爬行转移"。

## 追溯

修订由被授权的主 agent 做出并记录；人类所有者可在任意时刻否决，
否决后按 v1 重新评估全部 v2 证据。
