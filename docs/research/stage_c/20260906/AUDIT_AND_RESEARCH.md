# Stage C 审计、文献研究与独立反证

日期：2026-09-06。固定提交：`f3b452d56b2bedd5ea02249d4e5087b6ca151c47`。

## 1. 决策摘要

**启动最小联合规划是合理的，但“旧 planner 能力不足已经被完全证明”“下游已经修好”“升级就能通过 B1”均不成立。** 当前证据支持：旧实现有明确的表达能力缺口，而且存在会污染诊断的输入、坐标、候选区域和验收语义问题。应在同一个 Stage C 工作包里修正这些边界，再用相同输入比较新旧规划，而不是再围绕总拒绝数反复微调。

建议采用固定 running-trot 时序下的 **有限落脚事件组合 + 连续 SRBD/质心状态与接触力优化**。第一版是可执行的 C0 子集，不是全部 Stage C，更不是新一代全身 NMPC。只要满足输入、执行、实时性和安全检查，就尽早进入 B1 development canary；完整 frozen B0 与 B1 holdout 仍是正式验收条件。[R02–R05]

## 3. 关键发现与证据等级

### F01：shadow 与 terrain-actuation 的支撑输入不等价——确定的代码事实

`PublishTerrainControlSnapshot()` 只在 `terrain_actuation && have_high_state` 时计算 `actual_world_feet`，并且只有同一条件允许首次建立 force-backed 支撑锚点。H8/H9 明确关闭 terrain actuation。因而一个干净的 shadow-only 进程不会获得与 H5 actuation 模式相同的锚点初始化路径。[R07]

这不直接证明 H9 的支撑拒绝全部由此造成。但它推翻了“输入语义已经统一，因此这些拒绝只剩优化器能力问题”的前提。C0 的输入生成必须与是否向电机输出地形动作解耦；旧、新 planner 必须消费同一个不可变输入包。这个修复属于新规划器的必要输入基础，不是继续给旧 scorer 调参。

验证：A02、C++ guard 探针；Atlas 侧检查 anchor-valid、原始力、完整 FK 坐标、采样时刻，补一个实际调用路径测试。

### F02：H8 的 checked 全绿不能证明全链路一致——确定的检查流程事实

shadow 的 readiness 不通过时记为 code2、unchecked；commitment 更新不通过时记为 code3、unchecked。只有这些前置条件通过后才置 checked，再统计 code4。于是 code4=0 与 checked 样本全绿可以同时伴随 target/event mismatch、绝大多数无计划，不能据此宣布执行层已经可靠。[R09,R10]

报告中平地 441/6171、5cm 389/6266 才是整个所统计运动阶段的有效检查比例。并且工具中的“stable”按 `motion_stage==2` 选择，不等于已经证明姿态、速度与接触始终物理稳定。后续应分别记录模式窗口、物理质量和计划可用性，禁止把被预筛掉的失败从分母移除后报“100%”。[R02；A13]

### F03：支持联合规划的结构性证据确实存在——确定的代码事实，但不是唯一根因

现有 planner 为每条腿选择一个候选，再只做一次整体 `SupportFeasible()`。整个 horizon 的 body position、model COM、velocity/acceleration 都重复输入值；每条腿使用 `FirstTouchdownKnot()`，随后所有未来支撑复用同一落点。因此它既没有联合优化身体与落脚，也没有完整表达多次落脚事件。[R06]

A09 给出独立贪心失败、组合选择通过的几何例子，说明升级有合理机制。该例子不能替代 H9 的真实输入。A10 则反证“任何 support failure 都能靠 joint planner 修好”：如果失败发生在固定的初始 COM 和已落地脚上，未来落点无法改变这一刻，不能把初始状态挪到安全区或跳过 knot0。

### F04：所谓安全区域几乎退化为点——已独立复算

`BuildSafeFootholdRegions()` 计算：

`half = min(region_half_extent_m, 0.5*resolution_m - foot_patch_radius_m)`。

当前发布栅格分辨率是 float32 的 0.05m，足底 patch 半径是 0.025m。提升为 double 后，half 约为 `3.7252902846e-10 m`，整个区域宽度不足十亿分之一米；若使用精确 double 的 0.05，则 half=0，分支会跳过该区域。[R12,R13；A01]

因此不能把这些四边形直接喂给连续落脚优化器，声称已有可用的安全凸区域。第一版应明确使用已通过硬检查的**离散中心点**。以后若加入连续移动范围，需要对观测 patch 的并集做足底膨胀/边界收缩，并验证整个区域，而不是给 half 人为加 epsilon。

### F05：零 known cells 有具体的传感器边界候选原因——代码事实，运行归因尚待确认

模拟 lidar 的世界缓存宽440、高80、分辨率约0.05m、原点(-2,-2)，范围约为 x∈[-2,20)、y∈[-2,2)。越界射线点和窗口查询会被跳过；发布地图仍可能保留有效的维度、时间和来源。`TerrainModel.valid()` 不要求至少一个 known cell。[R11,R13]

H9 报告的 no-safe 行里约95.2%同时 zero-known/zero-regions。应先对齐当时的世界位姿、地图窗口和射线命中，判断是否到达缓存边界、姿态/FOV 问题或其他观测失效。不能把这些行解释成“联合搜索不够强”，也不能为某个测试场景偷偷放大世界边界。[R02；A03,A13]

如确认世界缓存问题，可做通用滚动地图或显式边界无效处理，作为独立 sensor 修复提交；模拟器 hash、回归和证据需要重新绑定。保持未知为未知，不使用场景真值填地形。

传感器模型还有外推边界：发布器包含从每个局部栅格上方垂直向下的密集射线，并按模拟geom信息跳过非目标碰撞体。这是理想化的射线高度图，不能直接等同于真实机载LiDAR的视场和遮挡。它与controller直接读取场景坐标是不同问题；当前仿真合同应明确承认这一传感器模型，研究报告不能把它包装成已验证的真实感知能力。[R13]

### F06：坐标和 freshness 必须先定义清楚——确定的数据路径风险

模拟高度图叫 `base_link`，但局部 XY 只按 yaw 旋转，高度是 world_z-base_z；这是一个重力对齐的 heading 局部表示。真实 body-frame FK 足端不能只用 yaw 转到世界系。当前 fallback 仍存在 yaw-only FK 路径；map copy 与控制状态各自取最新值，没有在所读 worker 输入路径看到完整的采样位姿重投影。[R06,R07,R11,R13]

A06 的合成例子显示，仅5° pitch 就能使某个脚位的 x 差约3.1cm；这不是 H5 的实测误差，但说明在讨论0.624mm裕度之前，必须统一 frame 与时间。地图必须附采样位姿、观测时间与实际覆盖，COM 必须区别于 base origin；不能仅重写 timestamp 使输入“同 tick”。

### F07：扩大 horizon 不等于获得正确预测，也不等于允许延长 TTL

H8 shadow 配置为24个20ms节点，最后节点0.46s，同时把 plan_validity 设为0.46s。若消费年龄0.30s，MPC 8个30ms预测点的最后一点在0.51s；完整控制区间末端更晚。仍然不覆盖。而旧 planner 的后续节点还会重复首次落脚。[R06,R08；A04,A11]

预测覆盖、输入 freshness、可重新接纳时间和已经承诺的执行窗口应分开。旧计划因长期没有新解而“变老”，不能解释成允许任意增大计算/通信延迟预算。

### F08：15mm 是几何规则，不是完整动态稳定证书

两脚时，源码返回 `min(沿线端点余量, 40mm-点到线段距离)`。当端点条件不限制时，15mm意味着被检查点离两脚连线不超过25mm。它忽略所需加速度、摩擦可行性和角动量演化。[R06]

A07 构造了不通过这一几何规则、但**瞬时**接触力与零力矩可行的状态；A08 构造了几何通过、但给定加速度违反摩擦约束的状态。这不证明原规则该删除，也不证明某一动态轨迹安全。它证明：联合优化必须加入动力学可行性，同时保留冻结几何门槛独立计分；若门槛与真实初始状态冲突，提交反例要求正式决策，禁止换名字后偷偷通过。

### F09：分析器有需要明确裁决的条件冲突——新发现，不能由 agent 自行修合同

`transfer_mpc_support` 要求存在 transfer 样本，而且整个记录的 MPC horizon 最小接触数≥2。当前路线允许 running-trot 腾空段。如果一条含0-contact的预测被纳入 transfer 样本，它必然失败。A12给出最小反例。[R03,R04,R15]

这不证明所有 B1 都不可能：某些低速时序可能没有腾空。但它意味着“固定保留现行小跑时序”与“所有 transfer horizon 均≥2”不能无条件同时承诺。必须逐项映射 transfer 的生产代码触发条件、时间窗口与原合同目的。**不得靠不设置 transfer flag、伪造两脚接触或删去这些样本获得 PASS。**

另一项是水平 reference span≤1mm。现有 SRBD solver 在未启用 time-indexed reference 时，会在内部按速度自动推进位置参考；这与日志里 supplied anchor 的 first/last span不是同一量。[R14,R15；A14] 新设计分别记录 Phase1命令、实际solver参考和优化预测，不能用“COM trajectory只是预测”来掩盖已经改变了执行命令。

### F10：实时性和安全模型不能靠论文或旧 CTest 代替验证

当前 SRBD 通过 force-only dense QP求解，并动态建立凝聚矩阵；输出只包含第一步力与预测状态。把 horizon增大、再对多个候选组合反复求解，会改变计算规模。旧33/33、2ms目标及强CPU都不是新优化器时限证明。[R14]

旧 WBC周期性更新MPC，shadow与真实gait也不是同一个消费者管理器。[R10] 应引入可核验的 accepted execution bundle，而非每次 planner publish就让WBC切新plan、MPC却继续用旧力解。只能在数据契约与局部测试验证后接入新路径，不重写已有B0控制器。

## 4. 文献选择：借鉴机制，不照搬成功结论

这是有针对性的原始文献与2025–2026方向扫描，不声称穷尽所有最新方法。下表“对本项目选择”是本次工程判断。

| 路线/来源 | 已核实的机制与限制 | 对本项目的选择 |
|---|---|---|
| TAMOLS [P01] | 联合base pose与footholds，固定gait降低问题规模，使用有假设条件的动态稳定模型；论文称在线求解低于10ms。 | 支持joint方向与固定时序起步；不把其判据等同于现有15mm规则，不直接承诺2ms，也不复制未知区域外推策略。 |
| Perceptive NMPC [P02] | 凸落脚约束、地形预处理、SQP/RTI；Table IV的MPC迭代均值6.6ms、最大9.8ms，环境与硬件不同；文中承认逐腿区域选择和时间一致性的局限。 | 借鉴预计算和多项状态联合约束；完整系统规模大于C0，不能靠引用它证明当前deadline可达。 |
| MPC+WBIC [P03] | 简化模型预测反力、全身层形成关节命令，强调动态反力而非只追踪机身位置。 | 保留SRBD/ID-WBC路线；C0必须输出受力与身体预测的一致解释，不能只把COM曲线画得好看。 |
| Optimal Region Selection [P04] | 把区域选择和whole-body MPC结合。 | 支持跨腿/事件组合的重要性；不证明任何特定H9输入可行。 |
| Mixed-integer convex planning [P05] | 同时处理接触、步态和运动离散/连续选择。 | 用作小型fixture离线oracle的思路；第一版不引入大规模MIP求解器与新gait搜索。 |
| BiConMP [P06] | 利用机器人动力学结构做全身在线规划，并研究时域/频率影响。 | 后续结构化求解对照；不为C0引入整套替换。 |
| Whole-Body MPPI (2025) [P07] | 作者展示采样式全身控制及接触丰富任务。 | 有价值的替代研究路线，但不解决当前已有管线的输入与合同歧义，C0暂不切换。 |
| 本体感知联合估计 (2026) [P08]；冲击鲁棒MPC (2026) [P09] | 分别关注地形/接触/状态耦合估计，以及Go2冲击模型误差。 | 提醒感知和动力学误差应单独归因；无证据支持此刻跳过joint/接口而转入学习或鲁棒控制重构。 |

求解器上，先建立可测的最小QP接口，并以现有DenseQP作为参考实现；不假设它能满足多候选预算。若瓶颈明确在该后端，可在新路径对照固定维度的OSQP生成代码，或后续更复杂SQP使用acados；OSQP的无动态分配/固定稀疏模式支持只是工程特性，不是本项目硬实时保证。[S01,S02]

## 5. 独立反证：这套推荐可能错在哪里

| 反方假设 | 现在的证据 | 最小判别方式 | 对决策的影响 |
|---|---|---|---|
| 全是输入/地图错误，joint没有必要 | 锚点guard与地图边界确实存在；尚缺同输入对照 | 原始输入→规范化输入，分别运行旧planner；不要同时改算法 | 若规范化后旧法已持续可用，joint的增益需要重估，不能为了路线面子升级。 |
| 冻结support规则拒绝合法初态 | 几何反例成立；H5完整坐标缺失 | 固定真实x0和实际接触，分解margin，独立受力可行性检查 | 对该输入优化未来落点无效；提交契约冲突，禁止伪造初态。 |
| 最优组合存在，但beam漏掉 | 有限搜索本就不完备 | 小fixture穷举vsbeam，记录裁剪与预算耗尽 | “search exhausted”不能记成“物理不可行”。 |
| rollout可行而实际腿撞台阶 | SRBD不含完整腿扫掠/触地冲击 | 使用执行的同一条足端轨迹与FK碰撞检查，再做短闭环canary | 不能把质心QP success当B1证书。 |
| joint正确但超过2/5ms | 文献时间不能保证目标；现有dense矩阵扩大有风险 | Atlas上固定候选/节点预算的全路径基准，记录所有尝试 | 先优化计算结构；确需改预算必须另立审议，不藏到计时范围外。 |
| code4=0只是预筛选后的幸存者偏差 | 已由调用顺序确认 | 统计全部运动窗口、输入可用窗口、ready/checked/valid三个分母 | 不再以checked-valid单指标放行。 |
| shadow通过仍影响命令或实时调度 | 同输入命令不变性尚未证明 | 成对状态回放比较命令字段；另做live B0运行回归 | 两种证明不能互相代替。 |
| joint看似进步只是改了sensor或metric | 原始报告字段缺失，可混淆因素多 | 一项变更一个提交；输入、传感器、算法、分析器分别hash | 不拼接跨候选证据、不改验收含义。 |

## 6. 希望、工作范围与研究价值

没有证据说明Go2的5cm跨越在这一模型控制路线下物理不可行；已有文献提供了可信的机制先例，但不同平台、传感器、接触与验收规则不能直接迁移。因此本轮判断是**值得实施C0并做闭环检验，不能量化成功概率或承诺几天通过**。

比“又加了一个优化器”更有研究价值的方向是：同输入下，逐腿与联合规划在可行性/控制质量上的差异；有限时域、多次落脚承诺和异步执行对失效的因果影响；保持未知区域严格拒绝时的可用性代价。需要原始fixture、清楚的消融、对照和闭环结果，不能把目前的调试记录包装成已验证的新算法贡献。

更正此前的指导：把H8的checked全绿说成执行层已干净、把H9比例当成联合规划的必然证明，都过强；“继续修旧planner没有研究价值”也不准确。正确边界是停止无目标调参，保留能消除真实混淆因素的最小修复，然后公平比较新旧方法。
