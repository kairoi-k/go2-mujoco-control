# WBC contact lineage audit: 43c5f5a
Scope: read-only inspection of `/home/che/dev/go2-workspace/feat-stage-c-joint-planner` and raw runs `wbc_active_flat_43c5f5a_20260907_0001` and `_0002`. No repository edits, build, or simulation.
## Direct answer
Inactive force zeroing is keyed by `qp_contact`, the final mask passed as `wbc_in.contact` in `trot_experiment_wbc.cpp:686-689`. The active-force solver creates variables only for true bits and lifts them with `force_map`; inactive outputs are structurally zero. This mask is not terrain `planned_contact`, and is not a robust-grace/fused mask.
The production WBC path does not call `MeasuredContactFusion`. The class exists in `contact/contact_state_filter.h:131-243`, but full-tree references are only its header and tests. `WbcShadowDiagnostics` fields for raw/fused/robust/grace (`trot_types.h:284-291`) are not assigned in production and are not logged.
## Mask sources
`UpdateWbcFull` derives `measured_contact` from `LowState.foot_force` through hysteresis (5 N engage, 3 N release) at `trot_experiment_wbc.cpp:146-161`; implementation is `contact_state_filter.h:19-43`. `qp_contact` starts as measured (`wbc.cpp:169`). During gait stage 2 or stop-hold it can be replaced by all-four hold, measured stance hold, all-four emergency hold, or a current gait schedule merged by `MergeRunningTrotContact` (`wbc.cpp:180-200`). Merge mode 0 returns schedule, mode 1 adds scheduled legs until two are active, and mode 2 is measured OR scheduled (`contact_state_filter.h:68-103`). Therefore measured-only and schedule-only bits are both possible, depending on stage and high-speed mode.
`contact_mask` is computed from `qp_contact` (`wbc.cpp:202-213`) and copied to `wbc_in.contact` (`686-689`). If a usable terrain plan exists, WBC additionally records `wbc_in.measured_contact`, `fused_contact=qp_contact`, and terrain `planned_contact` (`689-703`). Terrain planned bits do not write back into `qp_contact`.
The terrain planner has a separate measured source: `PublishTerrainControlSnapshot` samples `foot_force >= 5 N` directly about every 50 ms (`trot_experiment_control.cpp:103-210`), then `UpdateTerrainRuntime` sends that measured array to the planner and independently generates planned schedule (`213-279`). Thus planner measured and WBC measured can differ because of sampling and WBC hysteresis. `LowCmdWrite` loads the latest usable plan before WBC (`control.cpp:500-515`); WBC accepts it only when `usable_at` and knot lookup pass (`wbc.cpp:215-237`). Latest planner status can therefore be rejected while an older published plan remains usable.
## Attempt, fallback/cache, overlays, and recheck
1. Solve is called at `wbc.cpp:1097-1099`; hard stance failure retries with hard no-slip disabled (`1100-1105`). `wbc_attempt` snapshots the final solver return (`1107`).
2. Attempt certificate runs immediately after the snapshot (`1108-1135`).
3. Success stores `last_id_wbc_`; failure reuses it if present, otherwise returns (`1137-1149`).
4. Sprint pitch normal-force and direct propulsion overlays modify force and tau only on `qp_contact` legs (`1151-1282`). Cartesian PD overlay modifies tau only (does not update force), then clamps tau to +/-35 Nm (`1284-1314`).
5. Selected certificate runs after cache selection and all overlays against current `wbc_in` and selected `wbc_out` (`1317-1324`). Thus a reused old solution is current-state rechecked diagnostically. This is not an acceptance gate: `solver_ok=true` and `constraint_feasible=true` are written unconditionally after this point (`1375-1379`), while `id_wbc_ok` remains the current solve boolean (`1376`).
6. Candidate tau is copied from post-overlay `wbc_out.tau` (`1414-1424`) and then used by the feedforward/primary path.
Only aggregate timing is logged: `wbc_shadow_elapsed_us` covers the whole full-WBC shadow call; `wbc_full_certificate_elapsed_us` covers certificate passes. There are no per-QP, retry, cache-copy, or overlay timers.

## What raw evidence can and cannot prove
`data.csv` provides foot forces, thresholded `contact_FR..RL`, `wbc_shadow_contact_mask`, active count, conditional terrain measured/qpc/planned masks, plan IDs/status, attempt/selected solver and certificate summaries, selected-reused boolean, and aggregate timing. `contact_ground_truth.csv` provides MuJoCo terrain foot mask, per-leg GRF/touch, and full dynamics, but no WBC mask, QP variables, cache source, or overlay components; it also lacks a common control sequence ID with `data.csv`, so direct row pairing needs time alignment.
Missing are raw/fused/robust/grace masks, per-leg final WBC force and exact inactive-force evidence, per-leg ID tau, overlay deltas, clamp-before/after values, cache source tick/age, and stage timers. `wbc_full_id_contact_force_x_n` is only the four-leg force-x sum; `*_tau_ff` cannot separate ID tau from overlays.
Minimal next instrumentation should record one control tick containing measured, gait schedule, qp, terrain planned, and any future fusion/grace masks; cache source tick/age; and per-leg force/tau before and after each overlay. Until then, the cause of the observed mask disagreement remains unknown.
